# AGENTS.md

Guidance for coding agents working in this repository. `CLAUDE.md` points here.

## What this is

`crowd-media`: guests at a gig scan a QR code and upload phone photos/video, which land
in R2 and are later pulled to the home NAS. One Cloudflare Worker (TypeScript) plus
Workers Static Assets. Every request runs the Worker first (`run_worker_first: true`);
it routes `/api/*` itself and hands static paths to `ASSETS`.

## Layout

- `src/worker.ts` — thin router. `GET /api/health` (band-less, any host); otherwise
  resolve the band and dispatch `/api/*` (`GET /api/band` → `src/api/band.ts`). On an unclaimed
  host `/<band>` and `/<band>/` serve the root asset (the page) and `/` is 404 (no
  default band); every other non-API path goes to `ASSETS` unchanged, so the page uses
  absolute asset URLs.
- `bands.yaml` — bands, hosts, caps, `paused`, shows, themes, Turnstile sitekey.
  `task config` (`scripts/build-config.ts`, Node, build-time) validates it with the
  valibot schema in `src/config/schema.ts` and writes `src/config/generated.json`
  (committed). The Worker imports only that JSON: no YAML parser or validator in the
  bundle. `check`, `test` and `deploy` depend on `config`.
- `src/api/uploads.ts` — chunked upload API (`POST /api/uploads`, `PUT …/:id/parts/:n`,
  `POST …/:id/complete`, `DELETE …/:id`) streaming into R2 multipart, 32 MiB parts.
  Init checks the Turnstile token (`src/upload/turnstile.ts`, siteverify with an
  injected fetch) after the paused check and rate limit, before validation and the cap
  headroom check; no `TURNSTILE_SECRET` → 503. `src/upload/`: `validate.ts` (init body,
  type/ext allow-list, size cap), `keys.ts`
  (key protocol `<prefix>/<capture>__<credit>__<uuid8>.<ext>`), `token.ts` (the upload
  `id`: HMAC-signed, carries key/uploadId/sizes, so no per-upload state exists outside
  R2's multipart), `counters.ts` (`BandCounters`, SQLite DO per band: day and rolling-30-d
  byte caps; init only checks headroom, each part PUT charges its bytes to an in-flight
  ledger, complete commits them, abort refunds them, an upload idle 2 h is committed by the alarm).
- `src/config/` — pure helpers: `resolveBand` (Host listed by a band → that band;
  any unclaimed host → first path segment, stripped: `/shivs/api/band`), `pickShow`,
  `torontoDate` (06:00 rollover), `objectPrefix`, `themeFor`.
- `public/` — everything that ships as static assets. Nothing outside it is served.
- `src/page/` — upload page TypeScript, bundled by `task build-page` (`scripts/build-page.mjs`,
  wrangler's esbuild) into `public/app.js`, which is committed so a clean-checkout deploy works.
- `test/` — vitest suites, run inside the Workers runtime by `@cloudflare/vitest-plugin`
  (`vitest.config.ts` points it at `wrangler.jsonc`). Every outbound fetch goes to
  `vitest.config.ts`'s `outbound`: siteverify is answered by `test/fakes/siteverify.ts`
  (Cloudflare's test secrets), anything else fails with 599. One test hits the real
  siteverify; `CI=1` or `TURNSTILE_OFFLINE=1` skips it.
- `wrangler.jsonc` — Worker `crowd-media`: `main`, `assets` (`ASSETS` binding,
  `run_worker_first: true`), `observability`, `upload_source_maps`; bindings
  `MEDIA` (R2 `crowd-media`), `COUNTERS` (DO `BandCounters`, migration `v1`),
  `UPLOAD_RL` (rate limit, namespace `1001`, 120/60 s per band + IP); required secrets
  `UPLOAD_SIGNING_KEY` and `TURNSTILE_SECRET` (`.dev.vars` locally, from
  `.dev.vars.example`; tests set both in `vitest.config.ts`, Turnstile to Cloudflare's
  always-pass test secret; production `wrangler secret put`, which `wrangler deploy`
  requires to exist).
- `worker-configuration.d.ts` — generated by `task types`; committed. Regenerate after
  any `wrangler.jsonc` change.
- `Taskfile.yml` — `task dev | types | config | check | test | deploy`.
- `scripts/mock-api.mjs` — dev-only mock of `/api/band` + `/api/uploads*` (`task page:mock`); never shipped.
- `scripts/smoke-deployed.sh <url>` — asserts 200, 3 attempts; run after a deploy.
- `.github/workflows/deploy.yml` — PRs run `wrangler deploy --dry-run`. The push-to-main
  deploy job is inert until repo variable `CF_CI_DEPLOY` is `true`; local deploys are the
  chosen path.
- `package.json` — every dev dependency pinned exactly; no global installs. Node 22.

## Run, test, deploy

```bash
npm ci
task dev       # http://localhost:8787, no Cloudflare login
task check     # tsc --noEmit
task test      # vitest in the Workers runtime
task deploy    # wrangler deploy via `op run`, then smoke /api/health
```

Credentials for `task deploy` come from the 1Password Environment `crowd-media-deploy`,
mounted by the 1Password app at `./.env` (a pipe the app serves; gitignored). In it,
`CLOUDFLARE_API_TOKEN` is an `op://` reference, not a value; the deploy runs under
`op run --env-file=.env`, which resolves it inside that process only. Never read or
`cat` `.env`, never put a token value in the repo, a shell history, or an agent
transcript; if `.env` is absent, ask Mat to mount it rather than working around it.

## Adding a show / a band

1. Edit `bands.yaml`: a show is `id`, `venue`, `starts` with offset (`-04:00` summer,
   `-05:00` winter), optional `ends`/`theme`; a band copies an existing block.
2. `task check` — validates and regenerates `src/config/generated.json`; commit both.
3. `task deploy`.

## Infra lives elsewhere

All Cloudflare resources (R2 buckets, custom domains, routes, tokens) are Terraform in
`mp-infra` (github `mpataki/mp-infra`). `wrangler.jsonc` holds only bindings by name,
and those names must match what mp-infra creates. Do not add `routes`, custom domains,
or resource creation here.

## Conventions

- Conventional Commits, small and reviewable. Add files by name, never `git add -A`.
  No AI attribution in commits or PRs.
- Files under 500 lines; split when they grow.
- Vanilla TypeScript on both sides, no framework. The page is a form and a progress list.
- UI stays deliberately undesigned (plain HTML) until a dedicated visual pass.
- Tests run in the Workers runtime, are parallel-safe (random IDs, no shared state), and
  land in the same commit as the behaviour they cover.
- Verify by command output, not belief: `task check`, `task test`, and
  `npx wrangler deploy --dry-run` before handing off.
