# AGENTS.md

Guidance for coding agents working in this repository. `CLAUDE.md` points here.

## What this is

`crowd-media`: guests at a gig scan a QR code and upload phone photos/video, which land
in R2 and are later pulled to the home NAS. One Cloudflare Worker (TypeScript) plus
Workers Static Assets. The page is asset-served; only `/api/*` runs the Worker
(`run_worker_first`).

## Layout

- `src/worker.ts` — Worker entry. `GET /api/health` → `{"ok":true}`; anything else that
  reaches it falls through to the `ASSETS` binding.
- `public/` — everything that ships as static assets. Nothing outside it is served.
- `test/` — vitest suites, run inside the Workers runtime by `@cloudflare/vitest-plugin`
  (`vitest.config.ts` points it at `wrangler.jsonc`).
- `wrangler.jsonc` — Worker `crowd-media`: `main`, `assets` (`ASSETS` binding,
  `run_worker_first: ["/api/*"]`), `observability`, `upload_source_maps`.
- `worker-configuration.d.ts` — generated by `task types`; committed. Regenerate after
  any `wrangler.jsonc` change.
- `Taskfile.yml` — `task dev | types | check | test | deploy`.
- `scripts/smoke-deployed.sh <url>` — asserts 200, 3 attempts; run after a deploy.
- `.github/workflows/deploy.yml` — PRs run `wrangler deploy --dry-run`. The push-to-main
  deploy job is inert until repo variable `CF_CI_DEPLOY` is `true`; local deploys are the
  chosen path.
- `package.json` — every dev dependency pinned exactly; no global installs. Node 22.

## Run, test, deploy

```bash
npm ci
task dev       # http://localhost:8787, no Cloudflare login
task check     # tsc --noEmit
task test      # vitest in the Workers runtime
task deploy    # wrangler deploy via `op run`, then smoke /api/health
```

Credentials for `task deploy` come from the 1Password Environment `crowd-media-deploy`,
mounted by the 1Password app at `./.env` (a pipe the app serves; gitignored). In it,
`CLOUDFLARE_API_TOKEN` is an `op://` reference, not a value; the deploy runs under
`op run --env-file=.env`, which resolves it inside that process only. Never read or
`cat` `.env`, never put a token value in the repo, a shell history, or an agent
transcript; if `.env` is absent, ask Mat to mount it rather than working around it.

## Infra lives elsewhere

All Cloudflare resources (R2 buckets, custom domains, routes, tokens) are Terraform in
`mp-infra` (github `mpataki/mp-infra`). `wrangler.jsonc` holds only bindings by name,
and those names must match what mp-infra creates. Do not add `routes`, custom domains,
or resource creation here.

## Conventions

- Conventional Commits, small and reviewable. Add files by name, never `git add -A`.
  No AI attribution in commits or PRs.
- Files under 500 lines; split when they grow.
- Vanilla TypeScript on both sides, no framework. The page is a form and a progress list.
- UI stays deliberately undesigned (plain HTML) until a dedicated visual pass.
- Tests run in the Workers runtime, are parallel-safe (random IDs, no shared state), and
  land in the same commit as the behaviour they cover.
- Verify by command output, not belief: `task check`, `task test`, and
  `npx wrangler deploy --dry-run` before handing off.
